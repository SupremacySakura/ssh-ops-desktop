# OpsPilot 桌面端 UI 对齐设计稿规格

## 背景与目标

当前桌面端已经具备 MVP 核心操作能力，但界面采用深色侧栏、宽松卡片和以单栏为主的信息结构，与《SSH 服务器运维桌面软件：完整产品与技术设计文档》中的高保真设计稿差异较大。

本次重构的目标是在不改变 Rust Core 边界、不伪造运维数据、不削弱危险操作保护的前提下，使桌面端的视觉语言、信息密度和页面结构与设计稿一致，并为后续功能扩展建立可复用的 UI 基础。

## 本次范围

### 完整对齐的页面

- 全局应用壳层
- 仪表盘
- 服务器管理
- 远程终端
- AI Agent 工作区
- 项目管理
- Docker 管理
- Nginx 管理

### 统一视觉语言的页面

- 文件管理
- 任务与日志
- 设置

这些页面复用相同的页头、面板、表格、表单和反馈组件，但不在本次新增设计稿中不存在的业务功能。

### 不在本次范围

- 移动端页面和响应式移动端交互
- 长期时序指标存储
- 设计稿中存在但 Core 尚未提供的数据接口
- 为了填满界面而生成虚假服务器、告警、部署或监控数据
- 引入完整第三方 UI 框架或大型图表库

## 设计原则

1. **真实数据优先**：所有指标、列表和执行状态来自现有 Core。数据不可用时显示明确的空状态、未连接状态或错误原因。
2. **高密度但可扫描**：通过紧凑间距、对齐、分组和层级提升信息密度，不以缩小可点击区域换取密度。
3. **危险操作显式隔离**：生产环境标记持续可见；删除、部署、重载和高风险 Agent 操作保持二次确认与风险说明。
4. **页面结构一致**：列表型页面使用“筛选/工具栏 + 主列表 + 右侧详情面板”；工作台页面使用明确的多栏布局。
5. **无障碍可用**：状态不只依赖颜色；保留语义标签、键盘焦点和可读的错误反馈。

## 视觉系统

### 颜色与表面

- 应用背景使用极浅蓝灰色，导航、顶栏和主要面板使用白色。
- 主色为清晰的中亮度蓝色；成功、警告、危险和 AI 分别使用绿色、橙色、红色和紫色语义色。
- 边框为低对比冷灰色，阴影保持轻量，仅用于区分浮层和详情面板。
- 终端、日志和配置代码区域继续使用深色表面。

### 字体与间距

- 使用系统无衬线字体栈，中文正文保持 12–14px，页面标题保持 22–26px。
- 采用统一的 4px 间距基线，页面主要间距为 16–24px。
- 控件高度以 32–36px 为主，重要主按钮可使用 36–40px。

### 基础组件

建立不依赖第三方 UI 框架的轻量组件层：

- `Icon`：集中管理 SVG 图标，替代 Unicode 符号。
- `PageHeader`：标题、说明、面包屑或环境信息、主要与次要操作。
- `Button`、`IconButton`：统一 primary、secondary、ghost、danger 状态。
- `StatusBadge`、`EnvironmentBadge`：同时使用图标、文字和颜色表达状态。
- `MetricCard`：图标、标题、主值、补充信息和可选趋势。
- `Panel`、`SectionHeader`：统一卡片边框、间距和标题操作。
- `DataTable`：统一表头、选中行、悬停、空状态和操作列。
- `FilterBar`：搜索、下拉筛选、重置与结果计数。
- `DetailPane`：固定右侧详情区域，包含关闭按钮、标签页和滚动内容。
- `EmptyState`、`InlineAlert`、`Dialog`：统一等待、错误、空数据和确认反馈。
- `ProgressBar`、`MiniSparkline`：只展示已有实时数据；缺失数据时显示不可用状态。

## 全局应用壳层

应用壳层采用固定浅色左侧导航和固定顶部工具栏：

- 左侧导航宽约 216px，包含 OpsPilot 标识、九个主导航入口、许可证/状态区域和收起入口。
- 顶栏包含全局搜索入口、环境切换器、始终可辨识的生产环境提示、通知按钮和用户区。
- 当前路由使用浅蓝底色、蓝色图标和文字表示。
- 主内容区域取消过宽的居中限制，让数据表格和右侧详情栏充分利用桌面窗口。
- 窗口宽度不足时侧栏可收起；本次不将布局重排为移动端页面。

现有健康检查、Core 未就绪警告和版本信息保留，但改为顶栏或内容区内的紧凑状态反馈。

## 页面设计

### 仪表盘

- 页头提供新增服务器、打开终端和 AI 巡检等现有可用入口；不可用操作显示禁用状态和原因。
- 第一行展示服务器总数、可信连接数、运行中任务数和 Agent 状态。
- 主区域展示所选已连接服务器的实时资源指标，并保留手动刷新。
- 最近活动、服务状态、监听端口和服务器健康表使用真实数据。
- 不支持长期趋势时，不绘制伪造时间序列；以实时指标卡或“暂未启用历史监控”的占位说明替代。

### 服务器管理

- 页头保留新增服务器和批量导入操作。
- 筛选区支持现有名称/地址/用户搜索，并为环境、分组和认证方式增加前端筛选。
- 服务器表格支持选中行；选中后在右侧打开详情面板。
- 详情面板展示基本信息、环境、认证、最近连接和快捷操作。
- 新增/编辑、导入、私钥路径、主机指纹确认和删除确认继续使用现有真实流程。
- 详情面板不替代模态确认；危险操作仍必须经过原确认流程。

### 远程终端

- 顶部显示当前连接、服务器地址、环境和连接状态。
- 主体采用终端区与 AI 助手区双栏布局，终端为主要区域。
- 现有 xterm 视口、会话标签、命令输入、粘贴预览和会话恢复逻辑不变。
- AI 助手区复用现有 Agent 能力；没有可用 Agent 或模型时显示明确降级状态。
- 小窗口允许 AI 区折叠，不压缩终端到不可用宽度。

### AI Agent 工作区

- 顶部显示可用工具类别和当前作用域。
- 主区分为对话、执行计划和审批队列三列。
- 风险等级、目标范围、命令摘要和影响说明在审批卡中完整显示。
- 所有审批继续复用现有风险决策逻辑；UI 不绕过后端授权或执行边界。
- 底部 Trace 区展示现有任务与执行记录；字段缺失时不补造数据。

### 项目管理

- 采用项目列表、部署流水线/版本记录和右侧项目详情三块结构。
- 现有项目创建、部署和回滚能力保持原数据流。
- 流水线步骤只反映真实任务状态；无任务时显示首次部署引导。

### Docker 管理

- 顶部指标根据真实容器与镜像列表计算。
- 主区包含容器列表、镜像列表和右侧容器详情。
- 详情面板提供已有启动、停止、日志和进入终端能力。
- 资源使用只有在 Core 返回指标时展示，否则显示“指标不可用”。

### Nginx 管理

- 顶部持续展示“快照 → 配置校验 → 平滑重载 → 健康检查”的安全链路。
- 主区由站点列表、配置编辑器和右侧详情组成。
- 现有测试、应用和回滚流程保持不变，生产环境操作继续显示风险提示。

### 文件、任务与设置

- 文件管理使用统一工具栏、列表与预览双栏结构。
- 任务与日志使用统一表格、状态标签和详情查看结构。
- 设置使用分组面板和标准表单控件。
- 仅调整结构与呈现，不扩大各页面的业务范围。

## 状态与数据流

- `App` 继续负责健康状态、服务器目录、连接、Agent 可用性、模型配置和路由状态。
- 页面继续通过现有 `CoreClient` 接口执行读写，不在 UI 层复制 Core 业务逻辑。
- 页面局部选择状态，例如选中服务器、容器或站点，保留在对应页面组件内。
- 详情面板根据选中实体派生展示数据，关闭面板不会修改业务数据。
- 加载、空数据、部分失败和完全失败使用不同的视觉反馈。
- 并行探测采用现有部分成功策略，单项失败不会用零值冒充真实状态。

## 文件与组件边界

- `app/app-shell.tsx` 只负责导航、顶栏和内容容器。
- 新增 `app/icons.tsx` 集中管理图标。
- 新增 `app/ui/` 存放无业务状态的基础组件。
- 每个 `features/*` 页面负责组合组件、页面状态和 Core 调用。
- 全局设计令牌与基础规则保留在 `styles.css`，页面专属规则按功能分区，避免继续堆叠不可追踪的通用选择器。

不引入完整 UI 框架和图表库。简单趋势线使用可测试的 SVG 组件；真实交互图表留待存在长期时序数据后再实现。

## 错误处理与安全

- Core 初始化失败时继续显示可恢复的启动错误页，不出现白屏。
- 页面请求失败时保留当前已成功加载的数据，并在相关区域显示失败原因。
- 不把错误提示统一映射为“网络失败”；尽量反映连接、权限、凭据、数据缺失或功能不可用。
- 生产环境标识在全局顶栏持续可见。
- 危险操作按钮使用文字和图标，不只使用红色表达。
- 所有已有确认、主机指纹核验和 Agent 风险决策保持有效。

## 测试与验收

### 自动化测试

- 为基础组件补充键盘、ARIA、状态变体和事件测试。
- 更新页面测试，覆盖详情面板打开/关闭、筛选、空状态和原有核心操作。
- 保留并扩展终端原型冻结回归测试，确保 UI 重构不重新引入白屏。
- 更新 renderer E2E，验证全局导航和七个核心页面可渲染。
- 更新 native E2E，验证真实 Tauri 启动、仪表盘和终端导航。
- 执行桌面端单测、类型检查、lint、Vite 构建与 Tauri debug 构建。

### 人工视觉验收

- 1448×1086 窗口下，全局壳层、间距、色彩和信息层级与七张桌面设计稿保持一致。
- 服务器、项目、Docker 和 Nginx 页面具有稳定的右侧详情结构。
- 终端页面呈现终端与 Agent 双栏，终端仍可正常输入和调整尺寸。
- 无真实数据时页面保持完整、清晰，不出现虚假指标或大片无说明空白。
- 生产环境和危险操作在所有相关页面清晰可辨。

## 实施顺序

1. 建立设计令牌、图标和基础组件。
2. 重构全局应用壳层。
3. 重构仪表盘和服务器管理，作为列表、详情与指标组件的视觉基线。
4. 重构终端和 AI Agent 工作区。
5. 重构项目、Docker 和 Nginx 页面。
6. 统一文件、任务与设置页面。
7. 完成自动化验证、原生验证和视觉验收。

## 完成标准

当以下条件全部满足时，本次 UI 对齐完成：

- 七个桌面核心页面的布局与设计稿信息架构一致。
- 现有核心工作流和安全确认没有回归。
- 无伪造运维数据。
- 单元测试、类型检查、lint、renderer E2E、native E2E 和 Tauri debug 构建通过。
- 1448×1086 桌面窗口人工检查无白屏、遮挡、不可读文本或主要布局溢出。
