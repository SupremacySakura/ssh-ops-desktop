# xterm 与 Tauri 原型冻结兼容设计

## 目标

OpsPilot 在 `freezePrototype: true` 时必须正常显示仪表盘与终端页面，不能因 xterm 模块初始化失败而白屏。

## 方案

- 保留 Tauri 的 `freezePrototype` 安全加固。
- 通过 Vite 的版本锁定源码变换修补 `@xterm/xterm@6.0.0`，把对继承只读 `toString` 的普通赋值改成定义自有属性；目标片段变化时构建必须失败。
- 将终端页面改成 React 延迟加载，使终端依赖异常不会阻止仪表盘首屏启动。
- Renderer E2E 在页面脚本执行前冻结 `Object.prototype`，分别验证仪表盘和终端路由。

## 失败与降级

兼容变换与依赖版本严格绑定；升级 xterm 时必须重新校验目标片段。终端异步模块加载期间显示明确的加载状态，其他工作区不依赖 xterm 初始化。

## 验收

- 未冻结场景显示服务器总览与 Core 就绪状态。
- 冻结场景下仪表盘正常启动。
- 冻结场景下终端路由正常加载，控制台没有页面异常。
- 单元测试、类型检查、Renderer E2E 和桌面构建通过。
